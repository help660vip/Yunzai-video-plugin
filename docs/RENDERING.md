# 渲染环境

`common` / `htmlrender` 信息卡使用 Puppeteer；`htmlkit` 沿用回退到 `common` 的行为。浏览器不可用时回退到 `default` 文本输出，解析、下载和媒体发送仍按原配置执行。主题、字体、评论、二维码和长图规则不变。机器人实际发送的信息卡固定为 PNG，以兼容 OneBot / QQ 富媒体上传；公共 `renderCard()` 接口仍保留显式 PNG 和自动 WebP 输出能力。

## 默认选择顺序

未显式覆盖浏览器时，无需增加插件配置：

1. 检查消息运行时、宿主公开的浏览器或渲染器。对于调度器，通过其 `getRenderer()` / `getRenderer("puppeteer")` 获取实际后端；必要时读取已确认的 Miao-Yunzai / TRSS-Yunzai 根目录中的渲染器单例入口。只有 `render()` / `screenshot()`、无法提供当前模板所需 Page 能力的接口不作为浏览器使用。
2. 宿主不可用时，按 Node 实际模块解析结果查找插件、宿主可用的 Puppeteer 依赖，并优先使用各依赖默认解析出的配套浏览器。兼容 pnpm 的真实模块位置，不拼接版本目录。
3. 检查 `PUPPETEER_CACHE_DIR` 指定的缓存，以及当前服务进程用户的 `.cache/puppeteer`。只读取已知浏览器目录的浅层条目，不扫描其他用户目录；不按最高版本选取浏览器。
4. 检查 Linux 的常见 Chromium / Chrome 安装位置；保留 Windows 和 macOS 的系统浏览器兼容。

文件存在并不表示兼容。候选先检查文件、执行权限和 Linux ELF 架构，再启动 headless 浏览器，用无外网依赖的最小页面验证布局和 PNG 截图能力。验证成功的组合才用于业务渲染。不保证任意 Puppeteer 与 Chrome 版本都能搭配使用。

自定义主题从插件自有的空白 HTML 文档建立本地资源来源，不依赖 JSON 文档被 `setContent()` 隐式转成 HTML 的旧行为。主题资源仍限制在所选主题目录内，脚本和非授权网络请求继续禁用。

已有可用宿主浏览器时，不加载插件自己的 Puppeteer 来重新连接宿主。插件依赖要求的 Chrome 缺失，不妨碍直接使用宿主提供的可用 Browser。

## 显式覆盖

以下环境变量由实际运行 Yunzai 的进程读取，不是新增的锅巴配置项：

| 环境变量 | 行为 |
| :--- | :--- |
| `PUPPETEER_EXECUTABLE_PATH` | 指定浏览器可执行文件的绝对路径，优先于宿主和自动发现 |
| `PUPPETEER_BROWSER_WS_ENDPOINT` | 使用显式 WebSocket 调试端点，仅建立插件自己的连接 |
| `PUPPETEER_BROWSER_URL` | 使用显式 HTTP(S) 调试入口，仅建立插件自己的连接 |
| `PUPPETEER_CACHE_DIR` | 扩展独立浏览器的缓存发现位置，不跳过宿主优先流程 |

前三项只能设置一项。配置冲突、路径无效、连接失败或截图验证失败时，记录脱敏诊断并降级到 `default`，**不会悄悄切换到其他浏览器**。可在同一个显式目标上尝试已解析到的不同 Puppeteer 依赖。浏览器调试端点具有较高权限，应仅使用可信端点，不应将其公开到互联网。

## 资源与恢复

- 借用宿主 Browser 时，仅创建并关闭本插件的 Page / 独立 Context，不关闭、断开、重启宿主浏览器，不使用其他插件的共享 Page 或 `userDataDir`。
- 插件独立启动的浏览器由插件关闭；插件通过显式端点建立的连接仅执行 `disconnect()`，不结束远端浏览器进程。
- 并发初始化合并；每次渲染使用独立页面。失败 Promise 不永久缓存，断线后重新获取，迟到的页面、上下文和独立浏览器仍会被回收。
- 候选发现有上限；初始化最多尝试 6 个候选，单候选预算 8 秒、总预算 25 秒；业务页面默认限时 45 秒。资源释放另有短超时，不会无限等待。业务模板错误不等同于浏览器不兼容。
- 独立浏览器发现缓存最长 5 分钟；失败候选及重复诊断短期退避 30 秒。宿主能力动态重读，磁盘发现结果短期缓存。事件对象不存入全局渲染缓存。

## Linux / Debian 12 排查

以服务进程的用户、环境和依赖为准。nvm 安装的 Node、pnpm、`HOME`、`PATH` 及 Puppeteer 缓存位置可能与交互式终端不同；不要依据另一个用户的终端输出判断服务是否能找到浏览器。

日志记录候选来源、宿主 / 独立所有权、可取得的浏览器及 Puppeteer 版本、失败类别和最终降级。不输出完整调试地址、Cookie 或 Token。常见类别如下：

| 类别 | 排查方向 |
| :--- | :--- |
| `missing` / `not-found` | 该依赖默认配套的浏览器或文件不存在 |
| `permission` / `not-executable` | 服务用户对文件及父目录的访问、执行权限 |
| `architecture` / `wrong-architecture` | 浏览器与运行平台架构不匹配 |
| `shared-library` | Debian 运行库缺失；查看脱敏后的浏览器启动错误 |
| `sandbox` | 容器、内核或运行身份不满足浏览器沙箱要求 |
| `connection` | 显式连接目标不可用或宿主已断线 |
| `protocol` | Browser / Page API 或截图协议不满足要求 |
| `page` / `timeout` / `launch` | 分别检查业务页面、超时阶段或其他启动错误 |

独立启动保持 headless。普通用户保留浏览器默认沙箱；Linux root 沿用插件原有的 `--no-sandbox` / `--disable-setuid-sandbox` 例外。推荐按宿主部署规范使用普通服务用户。本次适配不新增关闭证书校验的参数，也不会修改宿主启动参数。

插件不会在启动或群消息处理中安装依赖、下载浏览器、升级 Node、删除缓存或清空 `node_modules`。确实没有可用浏览器时，日志会给出当前解析到的 Puppeteer 版本；管理员可在**对应依赖所在工程及服务用户环境**使用该依赖支持的安装命令，例如 `pnpm exec puppeteer browsers install chrome`。不要从诊断示例抄写固定浏览器版本。

## 开发验证

执行 `pnpm run check`、`pnpm test`。自动化测试包含 Linux 缓存布局、权限及架构、宿主调度器、版本错配场景、显式配置、并发、超时、断线恢复、所有权与脱敏检查，并保留本地静态主题及长图回归。模拟测试只证明相关逻辑，不等同于 Debian 12 实机验证；部署验证应另在对应 Debian 环境中完成，不需要访问内容平台或连接真实群。
